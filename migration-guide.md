# YAA design system migration guide

## Цель

Переносить дашборды без изменения данных, формул, фильтров и идентификаторов.
Меняется только визуальный слой: токены, темы, компоненты, типографика,
поверхности, таблицы и состояния.

| Область | Решение | Происхождение / статус |
|---|---|---|
| Primary | `#00E67E` | Brand YAA.pdf |
| Primary bright | `#00FF8C` | Brand YAA.pdf |
| Secondary | `#444FC5` | Brand YAA.pdf |
| Background | `#0E0E0E` / `#FFFFFF` | Brand YAA.pdf |
| Текст на primary | `#0E0E0E` | решение по контрасту |
| Текст primary на светлом | `#006B3F` | решение по контрасту |
| Success / warning / error | `#00E67E` / `#FFD166` / `#FF9871` | success из бренда; warning/error из текущей DS, error нужно подтвердить дизайнером; success text в light = `#006B3F` |
| Heading | `Druck Cyrillic Heavy` + `Druck Wide`/`Archivo` fallback | предоставленный файл опубликован по решению владельца; веб-лицензия пока не подтверждена |

| Elevation | `--yaa-elev-1`, `--yaa-elev-2` | v1 для карточек и dropdown/modal |

## Шрифты и публичный репозиторий

`InterTight.ttf` — variable-файл и покрывает рабочие веса `400/500/600/700`;
рядом лежит `fonts/inter/OFL.txt`. Все URL в `tokens.css` должны указывать на
существующие файлы. Предоставленный `Druck Cyrillic Heavy` опубликован в
`fonts/druk/drukcyr-heavy.ttf` по прямому решению владельца проекта; его веб-лицензия
пока не подтверждена и должна быть закрыта до коммерческого использования.
`Roboto Serif` удалён: его не было в брендбуке, он не используется
в токенах и занимал около 23 МБ. `Press Start 2P` использовался в старом Cerebro
только как декоративный retro-акцент; оставлен необязательный role token без файла.

## Контраст

Расчёт по WCAG relative luminance для основных пар:

| Пара | Контраст | Решение |
|---|---:|---|
| `#0E0E0E` на `#00E67E` | `11.60:1` | основной текст кнопки/бейджа |
| `#006B3F` на `#FFFFFF` | `6.61:1` | ссылки и primary-текст в light |
| `#FFFFFF` на `#444FC5` | `6.62:1` | вторичная кнопка |
| `#FFFFFF` на `#00E67E` | `1.66:1` | запрещено для обычного текста |

## Намеренно не перенесено

- `glow`, `blur`, `gradient text` — новая система использует плоские поверхности и
  жёсткие смещённые тени, чтобы не расползаться между темами и движками;
- radial green background — это старый декоративный паттерн, не базовый фон
  приложения; органическая графика остаётся в логотипе и брендовых материалах;
- яркий зелёный как текст на белом — заменён на `#006B3F` из-за контраста;
- старые translucent surfaces — заменены непрозрачными theme surfaces, чтобы
  Tailwind и статичный preview давали одинаковый результат.

## Tailwind v4

Для новых проектов после `@import "tailwindcss"` подключай:

```css
@import "./tokens.css";
@import "./dashboard-theme.css";
```

`dashboard-theme.css` через `@theme` переводит `gray-*`, `indigo-*`,
`emerald-*` и `green-*` в YAA-токены без `!important`. Это основной способ для
дашбордов, где исходные классы генерируются Tailwind.

Для уже собранной разметки можно добавить `dashboard-migration.css` после
utility-слоя и обернуть приложение в `.yaa-dashboard`. Этот fallback покрывает
обычные классы и отдельные `dark:bg-*`, `dark:text-*`, `dark:border-*` селекторы.
Он не меняет порядок или бизнес-логику DOM.

## Перенос одного дашборда

1. Обернуть корень в `.yaa-dashboard`.
2. Подключить `tokens.css`, тему и `dashboard-theme.css`.
3. Для legacy utility-классов добавить `dashboard-migration.css`.
4. Сохранить данные, формулы, фильтры и идентификаторы.
5. Заменить только фон, типографику, поверхности, границы, кнопки, статусы,
   таблицы и chart colors.
6. Проверить default, hover, active, focus-visible, disabled, loading и invalid.
7. Сверить цифры до/после и сделать dark/light снимки.

## Критерии готовности

- все значения идут из `tokens.css` или `@theme` bridge;
- на зелёном фоне тёмный текст, на светлом фоне зелёный текст `#006B3F`;
- нет запросов к отсутствующим font assets;
- обе темы читаемы и интерактивные элементы имеют `focus-visible`;
- каждый пункт старой системы либо перенесён, либо явно отмечен выше как снятый;
- решение, источник и спорный статус записаны в этом файле.

## Rollout

`yaa-events-dashboard`, `intickets-dashboard` и `yaa-fairytale-dashboard` имеют
ожидаемый Tailwind bridge из прежней матрицы; в этом репозитории они не доступны,
поэтому live-проверка остаётся отдельным шагом. `yaa_kz_dasbhoard` и
`yaa-marketing-brief` требуют smoke-test статичного подключения. Остальные фронты
нужно инвентаризировать отдельно. `Platinumlist` и `Chatpush` не входят в scope.
